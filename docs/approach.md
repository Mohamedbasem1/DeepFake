# Approach

## Task Reading

ImageCLEF 2026 deepfake detection is a binary `real` versus `deepfake` task.
The downloaded test archive includes an image detection split and an audio
detection split:

- `Data/Images_Detection/`: 24,404 `.png` files
- `Data/Audio_Detection/`: 11,520 `.wav` files
- `Data/Images_Detection_submission.csv`: `full_secret_name,prediction`
- `Data/Audio_Detection_submission.csv`: `full_secret_name,prediction`

The important constraint is that the organizers do not provide a training
dataset for detection. Test data may include organizer-generated fakes,
internet fakes, and fakes generated by other participants. That makes
out-of-distribution generalization more important than fitting a narrow local
training set.

## Competition Strategy

1. Build an inference-first pipeline.
   The submission writer, media discovery, frame sampling, and configurable
   threshold should work before we invest in model training.

2. Use pretrained general detectors as the primary signal.
   Start with a Hugging Face binary image classifier based on a modern vision
   backbone such as SigLIP/SigLIP2. Run it with horizontal flip test-time
   augmentation and average video frame scores when videos appear.

3. Add external validation instead of organizer training.
   Use datasets such as GenImage, Synthbuster, Fake2M, FaceForensics++ frames,
   or DFDC frames depending on what is available on Lightning. Keep validation
   sources separate so the final threshold can be calibrated by source.

4. Ensemble across detector families.
   A good final submission should combine:
   - pretrained HF image classifier score,
   - CLIP/SigLIP feature classifier trained on external data,
   - artifact/frequency score as a weak auxiliary signal,
   - optional face-crop detector for face-heavy media.

5. Calibrate, do not blindly use 0.5.
   After external validation is ready, choose the threshold that maximizes F1
   while monitoring precision and recall. If the portal ranks by several
   metrics, keep both a balanced-F1 submission and a high-recall variant.

## First Implementation Target

The repository now supports three detector backends:

- `artifact_baseline`: no pretrained weights; useful for smoke tests.
- `hf_siglip`: Hugging Face image classification backend for Lightning AI.
- `commfor`: Community Forensics checkpoint backend.

The current recommended first image submission is `commfor` with
`OwensLab/commfor-model-384`, because Community Forensics is trained for
general AI-generated image detection across thousands of generators.

Run on Lightning with:

```bash
pip install -r requirements-lightning.txt
python scripts/prepare_data.py \
  --zip data/ImageCLEF2026-DeepFakeDetection-Tes.zip \
  --output data/raw/imageclef_detection \
  --prefix Data/Images_Detection/

python scripts/run_inference.py \
  --config configs/image_detection_commfor.yaml \
  --input data/raw/imageclef_detection/Data/Images_Detection \
  --output outputs/images_detection_submission.csv
```

Before the official submission, confirm whether `prediction` expects numeric
`0/1` values or text labels. The current config assumes `1 = fake/deepfake` and
`0 = real`, which is the most common binary competition convention but still
needs portal confirmation.
